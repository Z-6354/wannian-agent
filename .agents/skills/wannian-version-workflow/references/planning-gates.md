# 规划计划版双门（P1 → P2）

适用：`2.x.1` 规划计划版。对话主场 → [review-protocol.md](./review-protocol.md)。  
字段模板 → [depth-templates.md](./depth-templates.md)。本文件**只**管过门流程。

```text
2.x.1
  ├─ P1 切分算法审 ──► 对话确认切分通过
  └─ P2 逐项细节审 ──► 每个后续 2.x.n 对话「通过」
           ▼
     才开该实现版（通常自 2.x.2）写实施单 / 生产码
```

P1 未过 → 不做 P2。某号 P2 未对话确认 → 不开该号写码。

---

## P1 · 切分算法审

| 检查 | 要求 |
|------|------|
| 类型首末 | 首=规划；末=清理；中间全实现（[numbering.md](./numbering.md)） |
| 体量 | 每一实现版 ≤ 单子代理/单轮；过大则拆、过碎则合并并说明 |
| 覆盖 | 已锁决议与周期目标均有落点；无悬空一句话 |
| 依赖 | 序正确；并行/重叠写明；禁区归属清晰 |
| 禁混 | 测文件/真人测不进普通实现版；清理职责只在末号 |

**动作：** 问题详单落盘（字段见 [depth-templates.md](./depth-templates.md) §P1）→ **对话中**按详单讲清 → 改正 → 用户对话确认「切分算法通过」→ 回写正式阶段表与采纳状态。

**禁止：** 未扫描就请整表签字；一句话目标冒充切分已审；「一行问题/一行改法」代详单；只丢计划链接。

无问题也须对话明示「未发现」+ 简短检查过程；详单仍可落盘。

---

## P2 · 逐项细节审

对**每一个**后续小版本（各实现版 + 清理版大纲）：

1. **落盘：** 完整可审规格写入 `docs/plans/`（如 `k05-2.x.n-p2-spec.md`）；维度见 [depth-templates.md](./depth-templates.md) §P2。  
2. **对话审：** 按节全文级搬入（[review-protocol.md](./review-protocol.md)）；默认一次一节。  
3. 每号独立对话「通过」（或书面豁免并落盘）→ 该号 P2 完成。

清理版 P2 至少：覆盖范围、三类测试清单、归档路径——不得只留「窄测+真人」四字；须对话呈现。

**门：** 对话通过 → 回写 status → 才开下一号 P2 或实现版。  
P2 已审 = 开做时的规格底稿；实施单可加细，**不得**无故缩水或偷换边界。

**禁止：** 「新建 TaskDraft / 实现 prepare」无字段或方法详单；答疑/搬入只给字段名无说明。
