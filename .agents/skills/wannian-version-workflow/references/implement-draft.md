# 实现版：草稿门 · 文件审阅卡 · 验收包

前置：该号已在对话中 **P2 通过**（[planning-gates.md](./planning-gates.md)）。  
对话主场 → [review-protocol.md](./review-protocol.md)。路径 → [artifacts.md](./artifacts.md)。  
本文件**只**管实现版落地与逐文件审。

---

## 1. 默认路径（强制，除非用户对话书面豁免）

```text
P2 已审 → 实施单 + MANIFEST（每文件含修改方式）
  → 新建 docs/plans/<k0x-2.x.n-draft>/（镜像生产相对路径）
  → 只在草稿写/改（禁止先改 wn-server/ / wannian-ui/）
  → 对话一次一文件：完整「文件审阅卡」（§3）
  → 用户「通过」→ 再拷生产（审查方式默认不拷写）
  → 全部已通过文件入仓后 → 对话交验收包（§4）
```

| 规则 | 要求 |
|------|------|
| 默认必须草稿 | 生产码先落 `*-draft/` |
| 对话逐文件 | 一次一个；草稿目录不是审阅主场 |
| 文件审阅卡 | 字段见 §3；禁止只报路径+「改了点东西」 |
| 仅已通过可拷 | 未对话确认禁止入生产树 |
| 豁免 | 仅对话明确「本号跳过草稿 / 直接改生产」并记实施单 |
| 小改 | 见 [diversions.md](./diversions.md)；一旦按实现版/MANIFEST 推进，仍默认草稿 |

实现中须改边界：停码 → 规划修订并对话重审受影响 P1/P2 → 用户再确认。

反模式：P2 过完直改生产；批量未审入仓；用实施单代替逐文件对话审；只丢 diff 链接。

## 2. MANIFEST 总表（落盘）

| 列 | 必填 |
|----|------|
| 序 | 是 |
| 路径（草稿→生产，或仅生产） | 是 |
| **修改方式** | 是（§3.1） |
| 一句话目的 | 是 |
| 规格锚点 | 建议 |
| 对话审状态 | 是（待审 / 已通过 / 已入仓 / 驳回） |

开审前可先对话丢总表，再按序一张完整审阅卡。P2 预告可先写「路径+方式+目的」；开做前不得缺修改方式。

## 3. 文件审阅卡（强制）

### 3.1 修改方式枚举

| 方式 | 含义 | 通过后 |
|------|------|--------|
| **增加** | 生产树尚无对等路径 | 拷草稿→生产（新建） |
| **删除** | 去掉已有生产文件 | 执行删除（或待删清单）；草稿可无正文 |
| **修改** | 改已有内容/签名/结构 | 拷草稿覆盖 |
| **审查** | 本号不改正文，只核现状是否符合规格 | **不拷写**；须补改则改方式后重审 |

后续新增枚举须先改本表与 [README.md](./README.md)，禁止自造同义词（如「更新一下」）。

### 3.2 每文件对话强制字段

| 字段 | 要求 |
|------|------|
| **名称** | 文件名；可附角色一句 |
| **路径** | 草稿 → 生产（删除则仅生产路径） |
| **修改方式** | §3.1 枚举 |
| **规格** | P2/实施单节号、断言、对象表、方法详单 ID |
| **方向** | 目标形状、边界、与邻文件分工（非「按规格实现」） |
| **修改原因** | 为何本号动它；守何不变量 / 填何缺口 |
| **参考代码路径** | 本仓锚点；同业/历史（学什么 / 勿抄什么） |
| **改动要点** | 增加：类型/方法清单；修改：关键增删改；删除：理由与调用方；审查：结论与证据 |
| **审序/依赖** | MANIFEST 序；先决是否已通过 |
| **请确认** | 对本文件：通过 / 修改意见 / 驳回 |

### 3.3 对话骨架

```markdown
### 文件审 · #<序> · <文件名>

| 字段 | 内容 |
|------|------|
| **名称** | … |
| **路径** | 草稿：`…` → 生产：`…` |
| **修改方式** | 增加 \| 删除 \| 修改 \| 审查 |
| **规格** | … |
| **方向** | … |
| **修改原因** | … |
| **参考代码路径** | … |
| **改动要点** | … |
| **审序/依赖** | … |
| **请确认** | 通过 / 修改意见 / 驳回 |
```

**自检：** 无草稿链接时用户能否凭卡片决定通过？否 → 补字段。  
**禁止：** 多文件一张卡「一并过」。

## 4. 验收包（实现版完成后 · 对话提交）

| 交付 | 说明 |
|------|------|
| 修改代码 | diff 范围或已入仓清单 |
| 逻辑说明 | 行为如何变、关键路径 |
| 理由 | 对应规格实现理由 / 不变量 |
| 自检 | 对照本版验收断言勾选 |

可另写入 reviews 供 AI 查询。用户对话验收通过 → 才开下一 `2.x.n`。
