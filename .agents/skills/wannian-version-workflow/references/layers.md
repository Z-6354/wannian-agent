# 三层步骤

编号/类型列 → [numbering.md](./numbering.md)。  
审阅怎么对话 → [review-protocol.md](./review-protocol.md)。  
本文件只写**各层动作顺序与产出**。

---

## 层1 · 立项（从 0）

**先讨论，再检索，再同步与多轮，最后落整体计划。**

| 步 | AI | 用户 | 产出 |
|----|-----|------|------|
| 1.1 讨论 | 想法、需求、约束、成功标准、不做 | 回答 | 需求草案 |
| 1.2 检索 | 网页 / GitHub / 论文 / 官方 docs / 同业 | 可补关键词 | `docs/research/` |
| 1.3 同步 | 汇报可吸收/勿抄 | 知悉 | research 更新 |
| 1.4 多轮改 | 引导改范围；决议落盘 | 确认 | 决议表 |
| 1.5 整体计划 | 目标、不做、**实现周期切分**、依赖 | **对话审过** | plans + roadmap/overview |

**门：** 整体计划对话审过 → 开层2。research ≠ 写码授权。  
路径约定 → [artifacts.md](./artifacts.md)。

反模式：未讨论先搜；不同步就落施工；research 里写排期。

---

## 层2 · 实现周期（2.x）

| 步 | 动作 | 产出 / 门 |
|----|------|-----------|
| ① | 从整体计划 / roadmap / research·契约·旧施工单**整理本周期相关文档清单** | 文档清单 |
| ② | 写出**本周期目标、含/不含、完成定义**，**明确告知用户** | 用户知情 |
| ③ | **检索**（同层1口径 + 本仓代码事实） | 本周期 research |
| ④ | 讨论并**敲定实现内容** | 决议落盘 |
| ⑤ | **列出全部 2.x.n 草案表**：序号、名称、**类型**、依赖、摘要目标 | 草案落盘（进入 `2.x.1`；**≠**已审） |

类型列硬规则 → [numbering.md](./numbering.md) §3。  
层2⑤ 未完成 = 不进入层3。P1/P2 未过 = 不进入实现版改码。

反模式：无阶段表就改码；用一句话表请用户「整表通过」后开码；上一周期清理未过就开下一周期。

---

## 层3 · 小版本（2.x.n）

中间实现版数量按敲定内容切；禁止把「一轮做不完」标成一个号。  
新周期：`2.x.1`=规划；第一实现从 `2.x.2`；清理占最大号。

| 位置 | 类型 | 做什么 | 细则 |
|------|------|--------|------|
| 第一 | **规划计划版** | P1 切分 → P2 逐项细节；默认不改生产码 | [planning-gates.md](./planning-gates.md) |
| 中间 | **实现版** | ≤ 单子代理/单轮；实施单 → 草稿 → 审阅卡 → 拷生产 → 验收包 | [implement-draft.md](./implement-draft.md) |
| 最后 | **清理总结版** | 审全部 + 三类测 + 清临时 + 归档 → 预备下一周期 | 本节 §清理 |

可审规格深度（字段级）→ [depth-templates.md](./depth-templates.md)。  
一切「请用户审过」的门 → [review-protocol.md](./review-protocol.md)。

### 清理总结版

须全部完成才算本周期收口：

| 步 | 内容 |
|----|------|
| 1 | **审核前述所有小版本**：规格 vs 已入仓代码；缺口列单并处理 |
| 2 | **测试（至少）**：（a）无相关上下文的子代理独立审（只给必要路径/规格/diff）；（b）软件测（窄测/回归）；（c）真人 live（忌 Fake） |
| 3 | 通过后：**清理**临时文件、未入档草稿、过期过程稿 |
| 4 | 计划/研究过程文档整合进 `docs/plans/archive/<周期>/`；更新 archive README 与 checklist |
| 5 | 汇报周期完成 → 预备开下一实现周期（回到层2） |

清理未通过 = 周期未完成；禁止宣称进入下一周期。
