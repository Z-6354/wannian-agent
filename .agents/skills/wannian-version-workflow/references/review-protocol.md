# 审阅协议（对话为主 · 子 Agent 旁路）

适用于 P1 / P2 / 文件审 / 验收包等一切「请用户审过」的门。  
P1/P2 步骤 → [planning-gates.md](./planning-gates.md)。文件审 → [implement-draft.md](./implement-draft.md)。  
本文件**只**管：主场规则、提问答疑、改计划派工。

---

## 1. 对话 = 用户主场 · 文档 = AI 账本

| 角色 | 用途 |
|------|------|
| **对话** | 用户说「通过 / 修改 / 驳回」。**不得**以「请去打开某 md」代替对话审阅 |
| **文档** | AI 落盘与换会话查询；用户可不主动打开。**不得**假设「文档已写 = 已审」 |

**硬规则：**

1. 通过门只认对话确认；`status: 已审` 只能在对话确认**之后**回写。  
2. 先落盘、再搬进对话：搬入该块实质正文（表、列表、字段、路径、验收、待决等）；允许按节切，**禁止**「三行摘要 + 请见文档」。  
3. **等价完整：** 用户只读对话也应能审完该块。  
4. 长规格默认一次一节（或用户同意的紧邻两节）；用户要求一次全份时可合并。  
5. **禁止：** 只丢链接；缩略表代审；「详见 §x」代替搬入；「摘要供审、全文在仓」。

**自检：** 删掉文档链接后，用户是否仍看得到该节全部可审信息？否 → 补全后再发。

落盘顺序（通用）：写 `docs/plans/` → 对话搬入 → 用户放行 → 回写 status。

## 2. 审阅中提问 → 子 Agent 答疑

用户**提问**（澄清、追证据、问现码）且**不要改文**时走本节。  
若要求改计划/改规格正文 → §3。

| 角色 | 职责 |
|------|------|
| **主 Agent** | 识别为提问；保持审阅锚点；派子 Agent；核对后用主口吻回复 |
| **子 Agent** | 只读查证，起草有证据答复。**不**主持门、**不**改计划/status、**不**写生产码 |

```text
通过/驳回 → 主 Agent 处理门
改计划     → §3
提问       → 保持锚点 → 子 Agent 查证 → 主 Agent 回传 → 锚点不前进
```

**选用：** 默认 `explore`；需综合用 `generalPurpose`；`model: inherit`（除非用户点名）。  
同条多独立问题可并行；有依赖则串行。  
同条既提问又通过 → 先答疑再处理通过。

**Prompt 至少含：** 用户原问；锚点与相关路径；已锁决议摘要；禁止改计划/status/阶段表/生产码/宣称已通过。

反模式：主 Agent 空谈不派查证；答疑子 Agent 改文档；把答疑写成「规格已通过」。

## 3. 修改 / 修复计划 → 带上下文子 Agent

例：「修复计划」「把 Q7 改成…」「计划写错了」。

| 角色 | 职责 |
|------|------|
| **主 Agent** | 识别改计划；保持锚点；组装完整上下文；核对 diff；汇报路径；**不**因改计划擅自标通过 |
| **子 Agent** | 只改允许路径内文档；回报改动与是否需重审。**不**写生产码；**不**偷标已审（除非 prompt 明确授权且用户已对话确认） |

**禁止裸派**——prompt 必须含：

```text
【用户原话】完整
【改动意图】否定的误解 / 要钉死的语义 / 近期问答结论
【审阅锚点】周期 / 2.x.n / 章节或草稿文件序
【允许路径】列全；未列出禁止改
【禁止】生产码；偷标已审；扩大未点名主题
【已锁决议】Q…/D…；澄清 or 用户改口
【必要摘录】将被改写的段落（勿假设子 Agent 有长对话记忆）
【交付】改动列表；是否需对话重审的节号
```

**选用：** 默认 `generalPurpose`；点状措辞可用 `explore` 但仍须带齐上下文。  
同条既改计划又通过 → 先完成改计划核对，再处理通过。

反模式：主 Agent 大段自改却声称已派子代理；prompt 只有一句「修计划」；子 Agent 写生产码或偷标已审。
