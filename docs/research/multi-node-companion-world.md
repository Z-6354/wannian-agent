## 1. 三层解耦（设备 ≠ 节点 ≠ 角色）

| | **设备 Device** | **节点 Node** | **角色 Role** |
|--|-----------------|---------------|---------------|
| 是什么 | 物理/虚拟机、电脑、容器宿主机 | 可调度的运行单元（进程/容器/服务实例） | 职责与权限身份 |
| 地位 | 运维资源，彼此无角色语义 | **同等** | **不对等** |
| 数量 | 1–n | **1–n**（可多于或少于设备数） | 当前烟火、世界树；可加 |
| 关系 | 一台设备可跑 **0–n 个节点** | 每个节点在 **恰好一台设备** 上；绑 **恰好一个角色** | 每个角色由 **0–n 个节点** 承担 |
| 数据 | 设备可挂盘，但**主历史不按设备复制** | 节点不私藏主库 | 领域归属角色，物理 **一份真源** |

```text
设备 Device（运维）          节点 Node（同等）         角色 Role（不对等）
┌─ 服务器甲 ─┐
│  Node-1 ───┼──绑定──────────────────────────► 烟火
│  Node-2 ───┼──绑定──────────────────────────► 世界树
└────────────┘     （同机双节点 · 完全合法）

┌─ 服务器乙 ─┐
│  Node-3 ───┼──绑定──────────────────────────► 世界树（与 Node-2 同角色，可互替）
└────────────┘

┌─ 电脑丙 ───┐
│  Node-4 ───┼──绑定──────────────────────────► 烟火（可选）
└────────────┘

绑定表可改；上图只是示意，不是常量。
```

**禁止说法**

- 「一台服务器 = 一个核 / 一个角色」——一台设备可多节点、多角色。  
- 「双核以后改成三核」——应说增加第 n 个**节点**或改**绑定**。  
- 「节点 = 角色」「设备 = 节点」——三层分开。  
- 「世界树角色对用户发 SSE」——角色权限不允许。

## 2. 绑定是配置，不是写死

**设备 ↔ 节点 ↔ 角色** 均解耦：

- 节点放哪台设备：配置  
- 节点绑哪个角色：配置  
- 同一角色多个节点：可互替（须角色内协调）  

**合法举例：**

| 配置 | 含义 |
|------|------|
| **仅服务器甲：两节点 = 烟火 + 世界树** | 单设备多节点；省机器时完全够用 |
| 甲=烟火节点，乙=世界树节点，丙=烟火节点 | **当前打算**的一种跨设备安排（见 §3） |
| 三节点皆烟火（可同机或分机） | 需单写者/租约 |
| 两节点皆世界树（可同机或分机） | 互为替换承担世界树 |
| 甲上三个节点绑三个不同角色 | 单机多角色 |

**定死机制 / 不定死部署表：**

- 定死：`deviceId`、`nodeId`、`roleId` 三分；节点→一设备、一角色；角色→0–n 节点；数据一份；角色权限表  
- 不定死：几台设备、每台几个节点、谁绑烟火/世界树、是否跨国

## 3. 当前打算的部署安排（示例 · 可改）

下列只是**近期默认之一**，与「只在服务器甲上开烟火+世界树两节点」等方案**同等合法**，改配置即可切换。

| 节点 | 设备（例） | **当前**角色 | 说明 |
|------|------------|--------------|------|
| Node-A | 国内服务器 | 烟火 | 一种默认用户入口 |
| Node-B | 国外服务器 | 世界树 | 一种默认事件源；宜轻量 |
| Node-C | 本地电脑（可选） | 烟火 | 可选扩容；不私藏主历史 |

**对照：同机双节点（也合法）**

| 节点 | 设备 | 角色 |
|------|------|------|
| Node-1 | 服务器甲 | 烟火 |
| Node-2 | 服务器甲 | 世界树 |

改绑定或增删节点/设备 = 改注册表，**不**改循环哲学，也**不**宣布「升级为三核产品」。

省资源：世界树角色节点宜轻；烟火角色节点承担重 LLM；同机多节点时注意 CPU/内存配额，避免两份全量重进程无意义叠加。

## 4. 数据一份

```text
唯一数据面（可独立 DB 主机，或挂在某设备可达路径上）
  · conversation / message / turn / memory / relationship
  · outbox / 审计日志
  · world_event / 世界树日程表（表属世界树角色，库仍一份）

所有节点共连同一真源（不论它们挤在一台设备还是跨三台）
❌ 禁止：按设备各一份主会话库
❌ 禁止：电脑节点私藏 transcript 当真相
```

## 5. 角色职责（当前）

### 烟火

- 用户向 AgentLoop（被动默认）。  
- 收用户消息；收世界树事件后可选分享。  
- 记忆 / 关系主体。  
- 用户 Channel / Outbox 属烟火角色（由哪个烟火**节点**投递可策略化）。

### 世界树

- 排日程、到点产事件；只交给烟火角色。  
- 不对用户维持人格对话。

### 日后其它角色

- 同样走节点绑定；权限由表定义。

## 6. 与循环 / 模块

| 模块 | 落点 |
|------|------|
| AgentLoop | **烟火角色**；跑在绑了烟火的节点上（不论该节点在哪台设备） |
| TurnEngine / 用户 Channel | 烟火角色 |
| WorldAgent | **世界树角色**；跑在绑了世界树的节点上 |
| DecisionPort | 烟火侧 |
| Persist | 共享一份；与设备数、节点数无关 |

同角色多节点：角色内租约/单写者，防双写。

## 8. N01 验收草稿

```text
[ ] 配置模型含 deviceId、nodeId、roleId；三者可独立变更
[ ] 能在**同一设备**上跑两个节点（烟火+世界树）并共一份 DB

[ ] 世界树角色进程无正式 /chat；宜轻量
[ ] 表述用「多核心 / 改绑定 / 同机多节点」，不用「双核改三核」
```

## 9. 废止与对照

| 废止 | 改为 |
|------|------|
| 双核、双核变三核 | 多核心，1–n 节点 |
| 一台服务器=一个角色 | 设备可多节点、多角色 |
| 节点=角色；设备=节点 | **设备 / 节点 / 角色** 三层解耦 |
| 写死 A/B/C 绑定 | 绑定是配置；当前安排只是默认例之一 |
| 仅同一 CompanionIdentity 多实例 | 那是宿主主备；与多核心拓扑分开 |
