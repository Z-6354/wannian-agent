## 1. 目标与非目标

### 目标

1. 深模块：执行一次工具 → 封闭结果（成功 / 拒绝 / 失败 / 未知）。
2. 内部完成目录、校验、策略、预算、操作身份存储、本机执行器；**不**泄漏给循环（测试替身仅限测试）。
3. **绑定解耦**：角色 × 模式 × 主机 → 画像 → 可见描述；加角色 / 模式 / 工具不改循环。
4. 烟火三模式工具表落地；**多角色绑定框架**可扩展（世界树等后挂，本批不装配世界树数据）。
5. 同角色在 Linux / Windows 上解析出**不同**可见集（能力求交可测）；Windows 上可见 PowerShell 解析工具，Linux 不可见。
6. **Windows 正确识别 PowerShell 7（`pwsh`）与 5.1（`powershell.exe`）**，避免十方常见「盲目调 pwsh / 只认 5.1」失败。
7. 循环：模型要工具 → 执行 → 观察回灌 → 再决策；次数打满强制回归。
8. 对话页默认烟火「聊天」模式可跑通至少一步工具（live 策略见 §8）。

### 非目标

- 世界树配置表 / 滴答画像 / 世界入站 / WorldAgent → **v0.3**（裁定 A：本批不做其内容，只留 §2.4 框架）
- Memory / Relationship / Outbox / Task → **0.2.3–0.2.5**
- **任意** bash/cmd/无白名单脚本执行；任意写盘、browser、computer、IM 写操作  
  （例外仅 §3.4 的受控 PowerShell **解析/只读探测**，不是通用 Shell）
- 开放插件、反射扫包、工具搜索 / 代码模式（契约可留注释）
- 解冻 `legacy/han-agent`
- 改写 0.2.1 会话锁 / 预算闸门语义
- 用空壳世界树角色或「契约 stub 测」冒充本批已支持第二角色

## 2. 绑定模型（解耦核心）

```text
                    ┌─ 角色允许表 ───────────────┐
工具目录 ──────────┤                             ├──► 生成可见集 ──► 工具描述列表
                    ├─ 模式 → 工具画像 ──────────┤         │
                    └─ 主机能力标签 ─────────────┘         │
                                                          ▼
                                              循环输入（只消费，不解析）
                                                          ▼
                                              执行一次工具（只执行，不选画像）
```

### 2.1 三层身份（禁止混用）

| 身份 | 含义 | 例子 |
|------|------|------|
| 角色 | 职责主体 | 本批：烟火；框架可加世界树等 |
| 模式 | 同一角色的工作模式 | 本批烟火：聊天 / 工作 / 科研 |
| 工具画像 | 一份工具成员列表 | 本批：烟火.聊天.默认、烟火.工作.默认… |
| 工具名 | 目录内唯一名 | 当前时间、计算器、读网页 |
| 主机能力 | 本机/节点能提供什么 | Linux、Windows、出站 HTTP、（探测后）PowerShell7 / PowerShell51… |

**规则：**

- 一个角色可挂多个模式（多对多）。
- 一个模式默认指向一个工具画像；日后可按通道覆盖。
- 一个画像含多个工具；一个工具可出现在多个画像（多对多）。
- 每个目录条目声明「所需主机能力」（可空 = 全平台）。
- 生成可见集：**先**取画像成员，**再**去掉本机不满足能力的工具，**再**生成描述。
- **禁止**在循环 / 模型口内写「如果是 Windows」；平台差异只进生成可见集 / 执行器登记。

### 2.2 扩展新角色（须零改循环）

加角色 = 加配置，不改循环实现：

1. 登记角色 + 允许的模式列表。  
2. 为每个模式指定工具画像与成员工具名。  
3. 若需新工具：目录登记 + 本机执行器 + 所需能力。  
4. 回合入口根据当前节点角色 + 会话模式生成可见描述。

验收：新增假角色时，循环源文件不增加对具体工具实现的依赖。

### 2.3 模式能否缓解「工具太多」？

**能，且应作为 0.2.2 主策略；不是完整按需搜索。**

| 手段 | 0.2.2 | 更后 |
|------|-------|------|
| 模式换画像（聊天少工具、工作/科研加只读检索） | **做** | 继续 |
| 主机能力求交（本机没有就不暴露） | **做** | 继续 |
| 通道/附件触发旁路画像（如日后识图） | 契约预留 | 更后 |
| 工具搜索（模型先搜再调） | 不做 | 工具数很大再议 |

模式 ≠ 多个灵魂：仍是同一个烟火身份；只换可见工具（人设语气属上下文，本批可只换工具）。  
「按需」= 编排侧按场景点名子集，不是模型侧自由发现。

### 2.4 多角色框架预留（本批只装配烟火）

**裁定 A：** 不实现世界树内容；**必须**把绑定写成可扩展框架，禁止 `if (烟火)` 写死业务。

本批须具备的框架能力（无世界树数据也可编译、可测烟火）：

| 框架点 | 要求 |
|--------|------|
| 角色 id | 稳定字符串/类型可新增；本批常量至少有烟火；**不**注册世界树成员表 |
| 模式 id | 按角色挂载；API 为「角色 → 模式列表 / 默认模式」 |
| 工具画像 | 「角色 + 模式 → 画像 → 工具名列表」；新增角色 = 加表项，不改循环 |
| 生成可见集 | 入参含角色、模式、主机能力；实现不假设唯一角色 |
| 循环 / 执行 | 只消费已生成的描述列表与「执行一次工具」；不知「烟火/世界树」 |

**禁止：** 在循环、校验、执行器里写死仅烟火；把角色枚举写成不可扩展的两值硬编码且无法加第三角色。  
**允许：** 本批启动装配只注入烟火的模式与画像；测试只覆盖烟火路径。

验收（框架，非世界树功能）：新增一个**测试用**临时角色 id（仅测、不进产品配置）时，只需加绑定表数据即可生成可见集，**不改**循环源文件。——此测验证扩展缝，不等于交付世界树。

### 3.4 Windows 特有 · PowerShell 解析（重要）

**痛点（已定要解）：** 不少 Agent 固定调 `pwsh`（机器上可能没有）、或只认 `powershell.exe` 5.1，导致 Windows 上「有壳却调不通」。L4 虽有独立 `pwsh` 工具，仍依赖部署侧装好后端；本项目要把**解析**做成一等能力。

| 项 | 规定 |
|----|------|
| 工具名（对外） | `powershell_resolve`（实现名自便；模型看到的稳定 id 固定此名） |
| 所需主机能力 | **必须** `os.windows`；Linux 目录可登记但不进入任何可见集 |
| 挂模式 | 烟火 **工作 / 科研**；**不**挂聊天 |
| 本批做什么 | **解析 + 只读探测**：选出引擎、返回路径/版本/版次标签；可选跑固定只读探测（如 `$PSVersionTable`） |
| 本批不做什么 | 任意脚本字符串执行、管道下载、持久会话、把解析结果当成通用 Shell |

**解析算法（验收必须对齐）：**

```text
1. 探测 PowerShell 7+
   - 查 PATH 上的 pwsh
   - 查常见安装路径（如 Program Files\PowerShell\*\pwsh.exe）
   - 能跑通且主版本 ≥ 7 → 记为 engine=pwsh7，记下可执行路径与 Version 字符串
2. 若无 7+，探测 Windows PowerShell 5.1
   - 通常 System32\WindowsPowerShell\v1.0\powershell.exe
   - 能跑通 → 记为 engine=powershell51
3. 两者皆无 → 拒绝（稳定 code，如 TOOL_UNAVAILABLE），不假装有壳
4. 两者皆有 → 默认优先 pwsh7；结果里同时列出 availableEngines，供模型知情
```

**成功观察须含（字段语义，JSON 形状实现自定）：**

- `engine`：`pwsh7` | `powershell51`
- `executable`：绝对路径
- `version`：人类可读版本
- `availableEngines`：本机实际找到的列表（可一项或两项）

**主机能力联动（阶段 2）：** 解析成功后，节点可点亮派生能力标签（如 `shell.pwsh7` / `shell.powershell51`），供**日后**受控执行工具求交；本批不因此开放任意执行。

**对照十方：** 不做「第二个 bash」；只保证 Windows 上**先认对壳**，这是很多 Agent 翻车点。

## 6. 0.2.2 内部阶段

```text
阶段 1  工具注册与识别
        行为链：注册 → 识别 → 校验 → 幂等 → 执行 → 收口
   ↓
阶段 2  角色与工具生成
        行为：按角色×模式×主机 生成可见工具清单
   ↓

        行为：要工具 → 执行 → 回灌 → 再决策；预算打满
   ↓
```

| **2** | 角色决定看见谁 | 烟火各模式 + Win/Linux 可见集不同；框架扩展缝可测 |
| **3** | 循环会用工具 | 一次工具往返 + 预算打满 |
| **4** | 产品路径能用上 | 对话默认聊天模式 + live |

## 9. 禁止的错误修法

- 在循环里按工具名或按操作系统分支。  
- 为 Windows/Linux 复制两套角色定义。  
- 给世界树对用户发消息类工具。  
- 用模式当多人格（分裂记忆/关系真源）。  
- 用工具搜索掩盖目录失控；反射扫包自动开放。  
- 操作身份只绑正文、不绑工具名/来源。  
- 工具拒绝另开第二套错误码，或正常拒绝打成内部缺陷异常。  
- **盲目只调 `pwsh` 或只调 `powershell.exe`**，不做 §3.4 解析。  
- 把 `powershell_resolve` 做成任意脚本执行入口。  
- **用「未实现」假执行器或占位成功冒充 0.2.2 已交付工具。**  
- **未经询问**就把后续版本能力写进产品路径当空壳替位。
