## 0. 执行总则

1. **先读真源**：本文件、已审计划、`docs/guide/01-checklist.md` 的 0.2.4、`docs/research/in-flight-user-message.md` §11、相关生产代码。A 阶段还须读[阶段施工单](./k04-a-behavior-journal-implementation.md)；其后各阶段也要先建并审施工单。旧清单中“多会话侧栏不做”已被本次用户批准的范围取代，其余安全和事务约束继续有效。
2. **一个阶段只做其目标**：A 账本 → B 会话读写 → C 流与交付 → D 页面 → E 排队/标题 → F 测试与真人。若底层依赖要求把 E 的少量基础设施提前到 C，应在施工单中列明依赖，不能提前宣称 E 完成。
3. **普通阶段沿用仓库审阅流程**：先阶段讨论、生产文件草稿、逐文件审阅，再入仓和阶段代码审核。F 才集中写自动化窄测、回归与真人验收；已有测试不能故意破坏。本文不授权跳过这些门。
4. **不改老 migration**：从 V014 起追加 Flyway 迁移；先核对当前最高版本及已发布数据。每个新索引写出对应查询；核验 SQLite 查询计划和 2 核 2 GB 资源限制。
5. **保留现有领域入口**：Message 写入仍经 Turn 接收/提交路径；不要在 Controller、SSE Publisher 或页面直接改库。模型与工具调用只由 TurnEngine/AgentLoop 执行。旧同步 HTTP 路径在新路径稳定前保持兼容，不能造第二套 Loop。
6. **只展示允许公开的内容**：用户已定“流式回复正文与工具过程，不展示模型思考原文”。安全投影在服务端做，浏览器不接收再自行删除秘密。

## 1. 现状与不可忽略的缺口

| 当前代码位置 | 真实现状 | 0.2.4 必须处理 |
|---|---|---|
| `TurnController` | POST 先 receive，接着同步 `TurnEngine.execute`，最后返回整轮文本 | 新增快速接收和后台执行路径；不能仅把同步响应包装成 SSE |
| `ModelPort` / `OpenAiCompatibleModelAdapter` | `decide` 只返回完整 `ModelOutcome`；HTTP `BodyHandlers.ofString()` | 增量解析模型 SSE，同时积累完整结果供原有 Loop 决策与提交 |
| `TimeoutModelPort` | 执行超时和中断包裹非流式调用 | 流式调用也须受原截止时间、取消和资源上限约束；避免无限线程/连接 |
| `SqliteTurnStepJournal` | 单独获取连接，写失败仅警告；当前不与 Turn commit 同事务 | MEMORY_WRITE 与正式提交事实必须在 Committer 事务内写；不能把现有独立记录误称原子账本 |
| `SqliteTurnCommitter` | 已同事务写完成消息及 `TurnCompleted` Outbox，维护 `last_activity_at` | 延续该事实与交付分工；新增事件不破坏完成事件唯一性/顺序 |
| `ConversationStore` / `ConversationStatus` | 只创建、读近讯；仅 ACTIVE | 扩展列表、分页、状态与 CAS 命令；不在 Loop 中塞会话管理 |
| `/chat/app.js` / `api.js` | sessionStorage ID，整轮返回后渲染工具和回复 | 左侧列表、历史回读、运行中投影、状态归属；`api.js` 继续作为页面唯一 HTTP 出口 |
| `ManageAuthFilter` | 只覆盖 `/api/manage/**` | 统一覆盖聊天 HTTP、SSE、历史补发及 internal；不能假定 SSE 自带鉴权 |

## 2. 核心架构与真源

### 2.1 五类数据不得混用

| 类型 | 作用 | 可否在运行中出现 | 重启后真源 |
|---|---|---|---|
| `message` | 用户输入及完成的助手正文 | 用户输入在 receive 后已持久；助手正文须成功提交后才成为正式历史 | 是 |
| `turn` | RECEIVED/CLAIMED/RUNNING/COMMITTING/终态和执行权 | 是 | 是 |
| `turn_step` | 可审计的模型、工具、记忆、结束事实 | 允许记录已发生步骤；正式记忆写入须与提交同事务 | 是，但只经安全投影公开 |
| `outbox_event` | 事务提交后的可靠对外通知 | 仅提交后 | 是；按全局序号补发 |
| 运行中增量 | 尚未确定会提交的正文 token 与工具活动 | 是 | 否；重连按当前 Turn 状态与已提交历史校准 |

**禁止的捷径**：把运行中 token 写成已交付 Outbox；把 `AgentTrace` 或 `log.info` 当历史；用前端缓存充当会话真源；在恢复时再次 POST 用户输入。页面的“实时”与“可靠补发”由不同生命期的数据协作完成，不必假装同一张表解决两者。

### 2.2 建议深 Module 与接口责任

| Module | 对外责任 | 不应承担 |
|---|---|---|
| 会话目录 | 列表、搜索、状态迁移、标题 CAS、最近会话 | 模型调用、消息正文改写 |
| Turn 接收与调度 | 幂等 receive、同会话 FIFO、claim、取消、重启后恢复待执行项 | 页面渲染、厂商 SSE 解析 |
| 模型流适配 | 将厂商增量组装为原 `ModelOutcome`，并发出安全正文片段 | Turn 状态迁移、直接 Outbox 写入 |
| 运行事件投影 | Turn/工具运行过程的公开白名单、订阅和有界缓存 | 决定业务是否提交 |
| 已提交事件交付 | 按 Outbox sequence 读取、过滤、补发、推 SSE | 调用模型、重放工具副作用 |
| 历史投影 | 从 Message + 允许的 Step 生成页面历史和详情 | 执行 Loop、依赖当前工具目录重建旧详情 |

不要为了“解耦”创建一层层只透传的接口。新接口必须隐藏排序、事务、鉴权、增量组装或状态校准等真实复杂度。

## 3. 会话数据与状态

### 3.1 表与迁移指导

- 扩展 `conversation.status` 为 `ACTIVE` / `ARCHIVED` / `TRASHED`。采用追加列保存标题来源（自动/手动）、标题修订号、移入回收站前状态与删除时间；具体列名由施工单定。状态更新必须用预期 revision 做 CAS，不可读旧值后无条件覆盖。
- 归档和回收站不修改 Message 正文。`last_activity_at` 表示消息活动；`updated_at` 表示元数据变化。默认“最近对话”按可解释的最近活动排序，空会话以创建时间兜底；排序键加稳定 ID 作为并列裁决，分页不漏不重。
- 标题/正文全文搜索只覆盖已提交、允许用户回读的消息。可用 SQLite FTS5，但先验证运行时支持、建表/触发器或应用侧更新、升级回填、删除同步及查询计划。若 FTS5 不可用，施工单需给出在 2C2G 下可验收的有界替代，不能无界 `LIKE` 扫全库并取整表入堆。`content_json` 不能直接作为搜索展示正文，需按版本化 envelope 提取文本。
- 清空回收站涉及 `message`、`turn`、`turn_step`、冻结提交计划、Review Job、搜索索引和 Outbox 历史的依赖关系。先画出删除顺序与引用策略，再实现事务。长期 Memory/Relationship 具有独立语义：**删除会话不等于遗忘记忆**；页面应提示，如需遗忘使用现有记忆遗忘能力。不能靠级联删除误删跨会话记忆。
- 迁移必须覆盖旧库已有会话和默认标题；自动标题任务不得追着历史会话批量调用模型。

### 3.2 状态操作表

| 操作 | 合法源状态 | 结果 | 并发与异常 |
|---|---|---|---|
| 新建 | 无 | ACTIVE，临时标题 | 客户端请求 ID 幂等；空会话允许存在 |
| 手动改名 | ACTIVE/ARCHIVED | 状态不变，标题来源 MANUAL | 非空、长度上限、控制字符检查；CAS；自动标题晚到不得覆盖 |
| 归档 | ACTIVE | ARCHIVED | 运行中/有排队时拒绝并提示先完成或停止；不悄悄取消 |
| 取消归档 | ARCHIVED | ACTIVE | 恢复原历史；不自动重跑 Turn |
| 移入回收站 | ACTIVE/ARCHIVED | TRASHED，记住前状态 | 运行中/排队时拒绝；默认列表/搜索/最近候选排除 |
| 从回收站恢复 | TRASHED | 回到原 ACTIVE/ARCHIVED | 不能使同一会话同时被清空；CAS |
| 清空回收站 | TRASHED 且无活动 Turn | 不可恢复 | 产品界面明确确认；批量有界事务、失败可重试；备份保留另按现有策略 |

关闭标签、网络中断、切换会话只断开浏览器订阅，不等于 Stop。归档/回收站中的会话不能接收新 Turn；接收与改状态的竞态在同一持久化校验上裁决。恢复回收站后不自动重新执行旧失败/取消回合。

### 3.3 搜索与列表

默认列表仅 ACTIVE，按最近活动倒序分页；归档和回收站各有明确入口。搜索标题与消息正文，返回会话 ID、标题、状态、匹配来源、截断片段和可定位的 message ID/sequence；结果分页与稳定排序。搜索仅查用户可见文字，不查隐藏推理、模型 prompt、工具密钥或原始 `turn_step`。手动重命名应立即反映在列表、当前页标题和搜索索引。空查询回到列表，不应扫描全文。

## 4. 首轮 AI 标题

1. 新会话先有临时标题（沿用现有“会话 N”或等价）。只在**首个成功完成的用户 Turn** 后安排一次标题生成；接收但失败/取消的 Turn 不触发。调用与主回复分离，绝不延迟回复或阻塞 SSE 终态。
2. 标题任务只读取首条用户消息与已提交的首轮回复的有限长度片段，使用启用模型的受限辅助调用；设定超时、输入/输出上限、并发上限和失败终止策略。不能把完整会话、工具原始结果或密钥送去命名。
3. 任务用 conversationId + 首轮 TurnId + 标题修订号保证幂等。更新条件必须是会话仍存在、未进回收站、标题仍为自动临时状态且 revision/来源未被用户改写。迟到结果只会被丢弃，不回滚用户手动标题。
4. 清洗标题：单行、非空、长度上限、去控制字符；拒绝模型输出的额外解释或结构化垃圾。失败保留临时标题并记安全失败码；不反复每次打开会话就重试。
5. 标题生成专用提示词本版可以按现行代码规范放置；**全仓提示词文件化属于后续版本**，不借本需求扩大迁移范围。

## 5. Turn 接收、执行与取消

### 5.1 从同步请求过渡

现有 POST 在 `receive` 后同步 `execute`。0.2.4 页面需要“先得到 turnId、再订阅进度”，还要在 A 运行时接收 B 并持久排队。实施者应新增异步接收契约（可用新路由或明确的请求模式），复用原 `TurnCommitter.receive` 和 `TurnEngine.execute`；旧同步客户端先保持可用。不能分别维护两套 Message/Turn 提交逻辑。新接收响应应迅速返回 conversationId、turnId、入队状态和幂等重放标记，不等待模型。

调度必须根据持久 RECEIVED Turn 按同会话顺序执行；不得只把 Runnable 放内存队列。进程重启应能找到待执行项，但恢复前须遵循原 claim/lease 与 COMMITTING 冻结计划，不盲目重跑可能有副作用的工具。一个会话最多一个有效 RUNNING attempt；跨会话并发有界，不能因 SSE 连接数无限扩张工作线程。具体限额由阶段施工单结合现有 AgentBudget 和 2C2G 设定、验证。

### 5.2 followup 与 Stop

- B 在 A 运行时 receive 后为 RECEIVED，页面显示“已排队”，A 终态后再执行 B。顺序以持久化接收顺序裁定；不要以浏览器点击时间或线程锁等待顺序替代数据库事实。
- Stop 请求指向明确 turnId/执行身份。RUNNING 时让取消信号传入模型流、AgentLoop 和可取消工具；终态以数据库状态为准。处于 COMMITTING 时不得强制改 CANCELLED，返回“正在完成提交/无法停止”这一真实结果。
- 撤销未执行排队项只允许 RECEIVED，持久地改为 CANCELLED；不可删除输入消息后假装它没来过。重复 Stop/撤销必须幂等。
- 若工具已产生外部副作用，Stop 不承诺撤销副作用；页面提供安全状态说明。页面离开、SSE 断线不触发 Stop。

## 6. 模型与工具流

### 6.1 模型增量契约

- 对 `ModelPort` 增加可选增量观察能力或等价适配层；仍由**同一次**模型请求累积出原本的 `ModelOutcome`。供应商流中的正文 delta 可以向运行投影发出，但工具调用参数的分片必须先按 index/id/name 正确组装，得到完整合法 JSON 后才交给原工具策略执行。
- 不把供应商的 `reasoning_content`、隐藏推理 delta、原始请求/响应头或密钥透给 UI、账本公开投影或搜索。遇到拒绝、空正文、用量、finish reason、模型错误时，最终语义与非流式适配一致；不能因为已经显示几个 token 就把失败当成功。
- 处理跨 chunk UTF-8、SSE 多行/空行、`[DONE]`、不完整 JSON、工具调用交织与断流。HTTP 超时、总预算、取消、供应商限流和不支持 stream 的模型必须有明确失败或兼容策略。不能静默退回“整轮完成才伪流式吐字”并宣称达成验收。
- 可合并小 token 降低 UI 刷新频率；不得丢正文或改变顺序。模型调用结束后以完整 `ModelOutcome` 进入既有 Loop，最终正式答复只由提交后的 Message 确认。

### 6.2 工具活动和详情

运行中公开事件最少包含：turnId、executionId、同次运行序号、工具调用 id/operationId、名称、状态、开始/结束时间、安全参数摘要和安全结果摘要。先显示“调用中”，终态再更新同一工具卡；不能每个进度事件生成新卡。

外层回合详情展示按顺序发生的模型、工具与结束步骤；内层工具详情展示安全参数/结果、耗时和错误码。使用语义化按钮和 `aria-expanded`，键盘可操作。展开状态按稳定 step/tool ID 保存，增量渲染不重置。长结果按大小上限截断并提示；只有经过工具级可见性审查的结果才允许全文展示，不因用户说“所有内容流式”而输出密钥或敏感正文。

## 7. 账本、Outbox 与 SSE

### 7.1 账本加厚的硬门

0.2.3-L 已有 USER_INPUT、MODEL_CALL、TOOL_CALL、FINALIZE，但 `SqliteTurnStepJournal` 单独连接且失败仅警告。A 阶段必须区分两类事实：运行观察可尽力记录，**正式 MEMORY_WRITE 与对应 Memory、助手 Message、Turn 完成状态及 `TurnCompleted` Outbox 必须在 `SqliteTurnCommitter` 的同一数据库事务中落下**。现有 `FINALIZE` 仍是提交后的尽力运行观察，不把它冒充最终事务事实。不能在 commit 前独立插入“成功写记忆”的步骤；回滚不得留下成功 MEMORY_WRITE。`step_no` 在同一 Turn 内唯一且单调，进程重启/COMMITTING 恢复不能重复插入或碰撞。具体编号与幂等决议见[A 施工单](./k04-a-behavior-journal-implementation.md)。

历史详情只能从允许公开的结构化字段投影。现有 `TurnToolCallProjector` 把 `argumentsJson` 直接交页面，A 阶段须复核脱敏和工具策略；不得依赖前端屏蔽。`AgentTrace` 继续可作内存视图，不能当唯一真相。

### 7.2 两类 SSE 事件

| 类型 | 例子 | 可靠性与重连 |
|---|---|---|
| 运行中事件 | `turn.started`、`reply.delta`、`tool.started`、`tool.updated` | 临时；绑定 executionId + runSeq。可在当前进程有界缓存，断线重连先取 Turn 状态/快照；进程重启后不承诺逐 token 补齐 |
| 已提交事件 | `message.committed`、`turn.completed/failed/cancelled`、`conversation.titleChanged/archived/trashed/restored` | 先写 Outbox 后投递；按 sequence_no 补发；跨进程重启可恢复 |

完成事件须与消息/Turn 提交同事务。失败或取消的终态也要可靠可观察；若现有失败路径尚未写 Outbox，应在对应状态迁移事务补充，避免页面永远“生成中”。同一逻辑终态只产生一次。SSE 的 `id` 只用于持久事件 cursor；临时事件使用载荷内 `(executionId, runSeq)` 去重，不得把临时序号当 Outbox cursor。游标过旧、事件已清理或临时缓冲缺口时服务端明确要求客户端重新拉历史/状态，而不是悄悄跳过。

连接流程建议：先持久快照和 cursor，再订阅并补齐两者之间事件；或者使用能证明无丢窗的等价顺序。SSE 仅负责传输，收到事件不能触发模型或工具。浏览器可用 `fetch` 读取 SSE 以携带统一鉴权及自管 cursor；若用原生 `EventSource`，先解决认证头、跨域凭据和重连游标，不得留认证洞。心跳、写超时、慢消费者、连接数、队列容量和关闭清理必须有界；2C2G 不允许每个 token 一次 SQLite 写入或每连接一个无限等待线程。

### 7.3 前端合并规则

前端状态分三层：已提交历史、当前执行中的临时投影、当前会话选择。先按 message/step/turn 的稳定 ID 合并；重复的 Outbox sequence 不重复插入；`reply.delta` 只追加到对应 executionId 的临时回复。收到提交完成后用正式 Message 替换临时回复，再移除其临时态。失败/取消则显示终态并清理或明确标注未提交片段，不得将它混进已提交历史。

切换会话时先递增本地选择代号、取消旧请求/订阅，后续响应必须匹配当前 conversationId 与代号才渲染。历史响应晚到、旧 SSE 晚到、标题任务晚到均不得污染当前视图。自动滚动只在用户仍处于底部附近时跟随；用户展开详情或上翻时不要强制拉到底。

## 8. HTTP 契约清单

阶段施工单须写请求/响应 DTO、错误码、鉴权与分页边界。路径可遵循现有 `/api/conversations` 风格，以下为能力合同，不要求逐字照抄路径。

| 能力 | 最少输入/输出 | 关键限制 |
|---|---|---|
| 列表/最近 | 状态筛选、cursor、limit → id/title/status/lastActivity/revision | 不带消息全文；稳定分页；TRASHED 默认不可见 |
| 单会话详情 | id → 标题、状态、revision | 不存在、回收站、无权访问区分安全返回 |
| 历史 | id、message cursor、limit → 已提交消息、公开步骤、next cursor | 只读；不能触发 Loop/ToolRuntime |
| 搜索 | query、状态筛选、cursor、limit → 会话与匹配 message/片段 | 标题+正文；有界；不搜索密钥/隐藏推理 |
| 改名/归档/恢复/删除 | id、expectedRevision、操作 → 新状态与 revision | CAS，重复请求幂等，运行中拒绝相冲突操作 |
| 回收站清空 | 明确的清空命令 → 删除数/失败信息 | 不可恢复、UI 明确确认、批处理有界 |
| 异步接收 Turn | conversationId、clientRequestId、text → turnId/status/replayed | 同键同文回放、异文冲突；快速返回 |
| Turn 状态/停止/撤队 | turnId → 当前状态与实际动作结果 | 只能取消合法状态；COMMITTING 不假装已停止 |
| SSE/补发 | conversationId、持久 cursor → 公开事件 | 与历史同鉴权；不执行业务 |

错误使用既有稳定 ErrorCodes 风格；新增码集中定义，不在 Controller 临时拼字符串。状态冲突返回可行动的安全文案。API 列表和历史都加 limit 上限，防止一次拉全库。`api.js` 保持 `/chat/` 唯一网络出口。

## 9. 访问、隐私与运维

- 当前 `ManageAuthFilter` 只管管理 API；0.2.4 必须统一覆盖聊天读写、搜索、回收站、SSE、历史补发和 internal。沿用仓库已定最小单用户访问策略：回环/非回环行为、token 来源、代理头信任和同源页面策略要一致。任何一个只读接口漏鉴权都能泄漏整段会话。
- 前端渲染用户/模型/工具文本时使用文本节点或受控 Markdown 渲染；不能把工具输出直接拼进 `innerHTML`。若引入 Markdown，链接、HTML、图片与脚本协议要受限；无需为 0.2.4 引入新的复杂编辑器。
- 出站事件 payload 不含 Authorization、API key、隐藏推理、完整系统提示词或未审查的工具原文。日志只记录稳定 code、关联 ID 与脱敏摘要。Outbox/账本原有数据中的敏感字段要先审查，再开放历史详情。
- 监控指标至少能观察队列长度、运行中 Turn、SSE 连接数/断线、Outbox 待补发、模型流失败与标题任务失败；指标本身不得记录正文。资源验收沿用 2C2G 目标，不新开常驻 Python/Node 后端。

## 10. 故障与竞态处理矩阵

| 场景 | 必须呈现的结果 | 禁止行为 |
|---|---|---|
| 首轮模型流中途断线 | 页面显示连接重试；同一 Turn 状态可查询；最终以提交消息或失败终态校准 | 重发用户消息、二次工具执行 |
| 服务进程重启 | 已提交历史与 Outbox 可回读；未完成 Turn 按 claim/冻结计划恢复或标明失败 | 凭浏览器缓存宣称完成、盲目重跑副作用工具 |
| SSE 事件重复/乱序 | 按持久 sequence 与运行 `(executionId, runSeq)` 去重；缺口触发重同步 | 重复工具卡/重复正文 |
| 模型已吐部分正文后失败 | 临时文本被标识为未完成，正式历史无伪造助手完成消息 | 把临时正文落作 COMPLETED |
| 用户切会话时旧响应返回 | 只更新原会话缓存，不覆盖当前页面 | 把旧标题、工具或回复显示到新会话 |
| 首轮自动标题与手动改名竞速 | MANUAL 始终胜出；自动任务被 CAS 拒绝 | 自动标题晚到覆盖用户选择 |
| A 运行时连发 B/C | B/C 持久排队并按 receive 顺序执行；可撤 RECEIVED | 并行跑同会话 Loop、拒收并丢输入 |
| Stop 与完成提交竞速 | 数据库唯一终态；COMMITTING 只恢复提交 | 已完成后又写 CANCELLED |
| 归档/删除与新 Turn 竞速 | 持久状态与 receive 在同一校验序中裁决 | 已进回收站仍接收输入 |
| 清空回收站部分失败 | 已成功批次可核对，失败批次可重试，无孤儿索引/引用 | 无界单事务、静默丢消息 |
| 标题模型不可用 | 临时标题保留；聊天照常完成 | 阻塞主回复、每次打开重复生成 |
| 超大工具输出或慢客户端 | 结果截断/按需查，缓冲有界，慢连接断开后可重连校准 | 原文塞入 SSE/Outbox、无限内存积压 |

## 11. 逐阶段施工单与审核门

### A · 账本和公开投影

先画出 Memory 正式提交链，再决定 MEMORY_WRITE 在 Committer 的写入位置、Step 编号和 rollback 行为；审查现有工具参数投影。交付：新增 migration（如必要）、写入路径、安全投影、只读查询接口、回滚与脱敏证据。**禁止**提前写页面、把失败吞掉却宣称强原子。

### B · 会话存储和 HTTP

先定状态机、CAS、列表排序、消息分页与清空依赖图；再做追加 migration、仓储和 HTTP。全文搜索须先完成 SQLite 支持/回填/增量同步方案。交付 API 合同和查询计划证据。**禁止**把会话管理塞进 `ContextAssembler` 或模型提示词。

### C · 异步执行、模型流和事件

先定“快速 receive → durable 调度 → Loop”的单一路径、运行事件与 Outbox 事件表，再扩 ModelPort/适配器、SSE 发布/补发和 Stop 底层。最小垂直链须能流式完成无工具 Turn，再加工具流。交付时明确旧同步路径兼容和重启恢复行为。**禁止**用模拟逐字输出替代真实模型流、用内存队列当任务真源。

### D · 网页与会话管理

先做 `api.js` 的统一客户端，再做侧栏/搜索/归档/回收站/历史，最后接流式双层详情。页面状态以稳定 ID 归并，所有异步回调带当前会话代号。响应式窄屏、键盘、滚动和空态都要设计。**禁止**直接 `fetch` 散落在视图文件、切会话后旧流继续写当前 DOM。

### E · followup、Stop 与标题

连接排队状态、撤队和 Stop 的服务端动作与 UI；补首轮异步标题任务及手动覆盖守卫。真人文案表达“已排队”“正在停止”“提交中无法停止”“标题生成失败但对话正常”。**禁止**前端自说“已停止”而服务端仍运行。

### F · 版本末段验证

集中补窄测与回归、真人 live。测试必须覆盖矩阵 §10 的关键路径，尤其原子 MEMORY_WRITE、流式工具参数分片、断线重连、重复 Outbox、恢复零模型调用、标题竞态、双标签同会话单执行、回收站清空、全文搜索升级回填和鉴权边界。真实模型验收至少走“正文增量 + 一次工具调用 + Stop/followup + 页面重开历史恢复”。若供应商不支持某种增量形态，写明支持范围与证据，不以 Fake 冒充通过。版本末段更新 canonical 清单与路线图状态并产出 review 证据；未通过不得标 0.2.4 已交付。

## 12. 实施 AI 每阶段交付格式

每个阶段的施工单需列：目标、触及文件清单、禁止触及文件、数据库/接口变化、执行顺序、每文件审阅顺序、阶段不变量、具体失败处理、可观察验收、与下一阶段的交接。文件清单在阶段开工讨论时固定；发现必须新增文件，先说明原因和影响，再更新清单。代码审核时逐项指出“已证实/未证实”，不能用编译通过代替行为验收。

低能力实施模型遇到下列情况必须停止自行扩展并回报：需要改 Turn 状态机合法迁移、需要改变已发布事件含义、需要删除/改写旧 migration、需要将未提交正文持久为正式消息、需要放宽鉴权、需要让删除会话顺带删除长期记忆、需要引入常驻新运行时，或无法证明某步的事务/幂等/顺序性质。回报应包含具体文件、现状、两种可行方向与对验收的影响。
