## 0. 一句话验收（可测语义）

> 当某会话存在进行中对话轮（Busy），且该会话上 `NotifyPolicy=USER_VISIBLE` 的 Task 进入终态（`SUCCEEDED` / `FAILED` / `CANCELLED`，本号钉范围见待决 H1）时：  
> 结果写入 **durable 待交付队列**（不得仅内存）；**不**立刻插助手气泡抢当前 Turn。  
> 当该会话当前 Turn **COMPLETED** 后：按队列序将待交付项 flush 为**附带消息**（正文前带虚线分隔约定，或等价 UI 虚线），经既有 Message+Outbox 路径可见；flush 后队列项标记已交付。  
> `NotifyPolicy=SILENT`：不入用户可见队列。  
> 会话 **Idle**（无进行中轮）时本号**不**负责交付（→ 2.5.7）；可只探测并留下钩子/明确 no-op。  
> 本号**不**改 Executor/Gate/审核/定时晋升。

| | 新测文件入仓 |

**衔接**

- ← **2.5.4**：`acceptResult` 已写 `SUCCEEDED`/`FAILED` + `result_json`。  
- ← **2.5.5**：用户确认后才有 Task 行。

## 5. 方法详单

### 5.1 `TaskDeliveryService.onTaskTerminal`

| 项 | 内容 |
|----|------|
| **触发** | `acceptResult` 使 Task 进入终态之后（同进程紧随；失败不得吞掉终态写） |
| **行为** | 读 NotifyPolicy；SILENT→return。Busy→insert QUEUED。Idle→按 H2 |
| **幂等** | 同一 taskId+终态 attempt 不重复入队（唯一键或查重） |
| **副作用** | 只写 delivery 表；不写 background_task 状态机 |
| **本号** | **真** |

### 5.2 `TaskDeliveryService.flushAfterTurnCompleted`

| 项 | 内容 |
|----|------|
| **触发** | 会话 Turn→COMPLETED（钩：TurnRunListener / Outbox 消费后 / Committer 后——实施选最短且不丢） |
| **行为** | 取该会话 QUEUED（序 created_at ASC）；逐条创建附带助手消息 + Outbox（**不**重跑 Loop）；CAS→DELIVERED |
| **失败** | 单条失败不丢队（保持 QUEUED 或标记可重试）；不得假 DELIVERED |
| **本号** | **真** |

### 5.3 Busy 判定

| 项 | 内容 |
|----|------|
| **Busy** | 会话存在 status∈{CLAIMED,RUNNING,COMMITTING} 的 Turn（待决可含 RECEIVED——**H3**） |
| **Idle** | 否则 |
| **本号** | **真**（最小实现） |

### 5.4 UI（最小）

| 项 | 内容 |
|----|------|
| **行为** | 转录识别附带消息（前缀或 metadata）→ 虚线样式 |
| **禁止** | 独立侧栏页；气泡皮肤库 |
| **本号** | **真**（最小） |

## 9. 验收断言

```text
[ ] Busy + USER_VISIBLE + Task SUCCEEDED → 入队 QUEUED；当前 Turn 期间转录无附带气泡
[ ] 该 Turn COMPLETED 后 → 附带消息出现（虚线可识别）；队列 DELIVERED
[ ] SILENT → 不入队、无附带
[ ] Idle 终态 → 本号不错误交付（按 H2：no-op 或仅留给 2.5.7）
[ ] 同一终态不重复入队
[ ] flush 不调用 AgentLoop；不 receive 用户句抢 followup
[ ] 后台执行槽行为与 2.5.4 一致（Busy 不禁 dispatch）
[ ] 禁区零 diff；窄编译通过
```
