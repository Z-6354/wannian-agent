## 3. 实施顺序

1. **api Id** — 对齐 `TurnId`：`record` + `generate()` + `asString()` + null 校验。  
2. **kernel 枚举 + ScheduleSpec sealed** — Relative/At/Every/Cron；JSON 序列化形状留给 2.5.3 FrozenPlan，本号至少 `toJson`/`fromJson` 或 Jackson 友好结构供 Repo INSERT 用。  
3. **OriginTurn / TaskProposal / TaskDraft / ResolvedSchedule** — 字段对齐 P2 §4。  
4. **ScheduleResolver 接口 + DefaultScheduleResolver** — `resolve` + `advance`；relative offset 解析：`m`/`h`/`d`（及 `20m`/`2d`/`48h`）；cron via cron-utils UNIX。  
5. **TaskRuntime 接口 + DefaultTaskRuntime.prepare** — 校验组合；调 Resolver；分配 `BackgroundTaskId`；默认 retry JSON 常量（如 `{"maxAttempts":2}`）；三方法抛/返回未启用。  
6. **V024 SQL** — 列与 CHECK/索引对齐 P2 §7；`sub_agent_run` 对齐 kernel-reference。  
7. **Sqlite*Repository** — `insertCreated` 按 Draft 全列写入（含 SCHEDULED）；`findById`；SubAgentRun 空实现或 `UnsupportedOperationException`。  
8. **TaskRuntimeConfig** — `@Bean` Resolver、Runtime、两 Repo。  
9. **编译** — `mvn -pl wn-server/app -am compile`（走仓内 settings；窄编译即可）。

## 4. 关键实现要点

### 4.1 `prepare` 拒绝矩阵

| 条件 | 结果 |
|------|------|
| `source != USER_LOOP` | D1 |
| `WORLD_TICK` / `MEMORY_REVIEW` | D1 |
| `USER_SCHEDULED_NOTIFY` 且 spec==null | D1 |
| `inputJson` 空或 >D2 | D1 |
| 非法 offset / cron / everyMs | D1 |
| Resolver 失败 | D1 |

### 4.2 `insertCreated` 命名

方法名可保留 `insertCreated`，但须能插入 `initialStatus=SCHEDULED|CREATED`（按 Draft）；或改名 `insertFromDraft`——若改名，2.5.3 实施单跟随。**推荐改名 `insertFromDraft`**，避免 SCHEDULED 语义被方法名误导。

### 4.3 时间存储

DB 与 Draft 对外 ISO-8601 字符串；内存可用 `Instant`。行级 `timezone` 始终非空（D5）。
