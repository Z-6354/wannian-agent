## 0. 一句话验收（可测语义）

> 在合法 `TaskDraft`（立即或定时，已由 2.5.2 `prepare` 产出形状）进入提交计划后：  
> `freezeCommit` 能把 Draft **持久进 FrozenPlan**；`commit` 与助手 Message + Turn 完成 + 必要 Outbox **同一 JDBC 事务**内调用 `BackgroundTaskRepository.insertFromDraft`，按 Draft 的 `initialStatus` 插入 `CREATED`（立即）或 `SCHEDULED`（定时）。  
> 恢复路径：`frozenCommitPlan` 重建的 `CommitTurnPlan` **仍携带同一 Draft**（不得丢 task）。  
> `taskDraft == null` 的既有完成路径行为不变。  
> **本号不**改 TurnEngine 成功接线、**不**启用 BackgroundAccepted 热路径、**不**跑 Executor / tick。

## 2. 现状锚点（已核实 · 2026-09-27）

| 位置 | 现状 | 2.5.3 必须怎么动 |
|------|------|------------------|
| `CommitTurnPlan.taskDraft` | `Object`；非空 → unsupported | 改为 `TaskDraft`（可空）；合法 Draft 可提交 |
| `hasUnsupportedExtensions()` | `taskDraft != null` | **删除方法** + 删除 `SqliteTurnCommitter.commit` 调用点（E1=B） |
| `CommitTurnPlan.completeTurn(...)` | 末参固定 `null` | 增重载或新工厂：`completeTurn(..., TaskDraft? taskDraft)` |
| `FreezeCommitPlan` | 无 task 字段 | 增加 `TaskDraft taskDraft`（可空） |
| `SqliteFrozenPlanStore` | `CURRENT_FORMAT=3`；JSON 无 task | **升至 4**；编码/解码 `taskDraft`；读 v≤3 时 task=null |
| `frozenCommitPlan` 重建 | 调 `completeTurn` → task 恒 null | 从 FrozenPlan 还原 Draft 写入 `CommitTurnPlan` |
| `SqliteTurnCommitter.commit` | 拒绝非空 taskDraft | 匹配冻结计划后，若 Draft 非空 → `insertFromDraft(connection, draft, now)` |
| `BackgroundTaskRepository` | `insertFromDraft` 已实现 | **调用**；本号不改 Repo 签名（除非发现缺口先回报） |
| `TurnEngine` / `AgentOutcome.BackgroundAccepted` | 仍 `BACKGROUND_NOT_ENABLED` | **本号不动** |
| Migration | V024 已存在 | **不新建**迁移；不改 V024 列 |

## 3. 总原则

| 原则 | 对标 | 为什么 | 本仓落点 |
|------|------|--------|----------|
| Draft 只经 CommitTurnPlan 同事务落库 | k05 不变量 1；Memory Writer 同连接 | 禁止先 SSE 再异步 insert | `commitInTransaction` 内 `insertFromDraft` |
| 冻结计划可恢复、不可换稿 | 现有 freeze/commit | 崩溃恢复仍带同一 Draft | format 4 + decode |
| 立即/定时初态 | Q9；2.5.2 Draft | 插入态=Draft.initialStatus | CREATED vs SCHEDULED |
| 审核未开不等于可热路径假落库 | Q3 / N3 | 本号只开缝；谁把 Draft 放进计划由 2.5.5 | TurnEngine 本号不动 |
| 不发明字段 | N1 | 2.5.2 已定形 | 只序列化已有 TaskDraft 字段 |

## 5. 方法详单（Committer / Store）

### 5.1 `SqliteFrozenPlanStore` encode/decode

| 项 | 内容 |
|----|------|
| **声明** | （包内）`insert` / `find` / decode 路径升 `CURRENT_FORMAT=4` |
| **行为** | 写：v=4，含 `taskDraft` 节点。读：`formatVersion`∈[1,4]；v≤3 无 task 键 → taskDraft=null；v=4 按上表还原 `TaskDraft` |
| **失败** | JSON 损坏 / 缺必填 → 与现码一致抛 invalid；不得静默丢 Draft |
| **副作用** | 写 `turn_commit_plan` 行 |
| **本号** | 真 |

### 5.2 `TurnCommitter.freezeCommit` / `FreezeCommitPlan` 携带

| 项 | 内容 |
|----|------|
| **声明** | 签名不变（仍收 `FreezeCommitPlan`）；计划内已含 `taskDraft?` |
| **行为** | 冻结时把 Draft 写入 store；与进 COMMITTING 同事务（现有语义不变） |
| **失败** | 既有 RUNNING/lease/revision/PLAN_ALREADY_FROZEN |
| **本号** | 真（跟随 FreezeCommitPlan 字段） |

### 5.3 `TurnCommitter.frozenCommitPlan`

| 项 | 内容 |
|----|------|
| **声明** | `Optional<CommitTurnPlan> frozenCommitPlan(TurnId)`（或现签名） |
| **行为** | 从 FrozenPlan 重建时：**填入解码得到的 taskDraft**（可 null）；禁止再走「completeTurn 固定 null」丢 Draft |
| **失败** | 非 COMMITTING / 无计划 → empty（现语义） |
| **本号** | 真 |

### 5.4 `TurnCommitter.commit` + 同事务插入

| 项 | 内容 |
|----|------|
| **声明** | `CommitTurnResult commit(CommitTurnPlan plan)`（现签名） |
| **参数** | `plan.taskDraft` 可空 |
| **返回** | 既有 `Committed` / `Rejected` / … |
| **行为** | 1）取消「非空 task → UNSUPPORTED_EXTENSION」；2）与冻结计划比对时 **含 Draft 相等性**（见 §5.5）；3）在 `commitInTransaction` 内、助手消息与 Turn 完成与必要 Outbox 同一连接上：若 `taskDraft != null`，调用 `backgroundTaskRepository.insertFromDraft(connection, draft, now)`；4）插入失败 → 整事务回滚 |
| **失败** | 计划不匹配、状态非法、SQL 失败 → Rejected 或既有错误映射；**禁止** Message 已提交但 Task 未插入 |
| **副作用** | 可能多一行 `background_task`；无 SubAgentRun 插入（本号） |
| **本号** | 真 |

### 5.5 冻结计划匹配（Draft）

| 项 | 内容 |
|----|------|
| **行为** | `commit` 入参与库中冻结计划比对时，`taskDraft` 必须一致：双 null，或同 `taskId` 且关键字段一致（至少 `taskId`、`initialStatus`、`scheduleSpec`/`nextFireAt`、`inputJson` 哈希或全文）。推荐：解码后 `TaskDraft` 整对象 equals（record 语义） |
| **失败** | 不一致 → 与现「mismatchedFrozenPlan」同类拒绝 |
| **本号** | 真 |

### 5.6 调用方（本号范围）

| 调用方 | 本号 |
|--------|------|
| 测试/手工构造 `FreezeCommitPlan`/`CommitTurnPlan` 带 Draft | 允许（验证缝） |
| `TurnEngine.sealReply` 传入非空 Draft | **禁止改**（保持 null）；接线属 2.5.5 |

## 6. 事务顺序（钉死）

在既有 `commitInTransaction` 顺序上插入 Task 步（对齐 Memory Writer 同连接）：

```text
1. 校验 COMMITTING + 匹配冻结计划（含 taskDraft）
2. insertAssistantMessage
3. completeTurn → COMPLETED
4. 必要 Outbox（MessageCommitted / TurnCompleted）
5. 附加 Outbox
6. Memory / Relationship（既有）
7. 【本号新增】若 taskDraft != null → insertFromDraft(connection, draft, now)
8. touchConversationActivity
9. delete frozen plan
```

**说明：** 步骤 7 可紧挨 Memory 前后，但**必须**在 delete frozen plan 之前、且与 2–6 同连接；推荐放在 Memory/Rel **之后**、touch **之前**，避免 Task 失败时已删冻结计划。

**Outbox：** 本号**不**新增 Task 专用 Outbox 事件（侧栏/消息中心后号）。
