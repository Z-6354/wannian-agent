## 4. 关键实现要点

### 4.1 Deferred 语义

`DispatchOutcome.Deferred` **仅** concurrency gate（槽满）。**禁止**因主 Loop 调模型而 Deferred。

### 4.2 选行与 SCHEDULED

SQL：`status IN ('CREATED','READY')`；**永不**选未到期 `SCHEDULED`。排序：`updated_at ASC, id ASC`。

### 4.3 取消（F3）

一步到位 Task/Run → `CANCELLED`；有活跃 Run 先 `Executor.cancel` 再 CAS。不强制 `CANCEL_REQUESTED` 中间态。

### 4.4 F13 回写义务

写 `dispatchNext` / lease / deadline 核心路径时钉死不等式（建议起点：deadline 4m < lease 5m），满足「合法执行不被误标 LOST」。钉死后：

1. 改本实施单 §1 表 F13 一行；  
2. 改 P2 §10.2 为「已钉：…」。

### 4.5 交付侧

本号写 durable 终态/`result_json`；**不**写聊天 Message / Outbox（→ 2.5.6/2.5.7）。
