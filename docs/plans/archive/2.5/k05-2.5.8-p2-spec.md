## 0. 一句话验收（可测语义）

> 落库 `status=SCHEDULED` 且 `next_fire_at ≤ now` 的 Task（含 `relative`/`at`/`every`/`cron`）：  
> 进程内 **SchedulePromoteTicker**（或等价独立拍）在拍上 **CAS** `SCHEDULED → CREATED`（S1=A），写入 `last_fired_at`，**不**在本拍跑 Executor。  
> 随后既有 `BackgroundDispatchTicker` → `dispatchNext` 认领 `CREATED|READY` 执行；**禁止** `claimNextExecutable` 直接扫 `SCHEDULED`。  
> 本次 Run **成功**后：`NotifyPolicy` 仍走 2.5.6/2.5.7；若 `ScheduleResolver.advance(...)` 得下一火 → 同事务/紧随写 `next_fire_at` 并 **回 `SCHEDULED`**（不得标 `SUCCEEDED` 终结系列）；若 advance 为空（单次 relative/at 或系列耗尽）→ Task `SUCCEEDED`。  
> 失败/取消：按 §5.3；`requestCancel` 对未开火 `SCHEDULED` 仍可一步 `CANCELLED`。  
> Ticker **只比**物化 `next_fire_at`（不现场解析 cron 选行）。漏拍：到期后至多晋升一次进入执行池，**不**在一拍内追赶全部历史火点（S5=A）。

| 位置 | 现状 | 2.5.8 必须怎么动 |
|------|------|------------------|

## 3. 总原则

| 原则 | 对标 | 为什么 | 本仓落点 |
|------|------|--------|----------|
| 不变量 8 | k05 N2 | 执行号不扫未到期 SCHEDULED | Promote 独占；claim 仍排除 SCHEDULED |

```text

                              │         成功 + advance 有下一火
                              └──────── SCHEDULED ◄──────────┘
                                                 │
                                    成功 + advance 空 → SUCCEEDED
                                    失败耗尽 → FAILED
                                    cancel → CANCELLED
```

## 5. 方法详单

### 5.1 `BackgroundTaskRepository.claimDueScheduled`

| 项 | 内容 |
|----|------|
| **声明** | `Optional<TaskDraft> claimDueScheduled(Connection c, Instant now)` 或批量 `List<…> claimDueScheduledBatch(..., int limit)` |
| **行为** | 选 `status=SCHEDULED AND next_fire_at IS NOT NULL AND next_fire_at <= now`，序建议 `next_fire_at ASC, id ASC`；CAS → `CREATED`；写 `last_fired_at=now`（S4=A：晋升时记开火）；**本步不改** `next_fire_at`（下一火在成功后 advance） |
| **失败** | CAS 丢→跳过该行；不得假晋升 |
| **本号** | **真** |

### 5.2 `TaskRuntime.promoteDueScheduled`（新建）

| 项 | 内容 |
|----|------|
| **声明** | `int promoteDueScheduled(int limit)`（返回晋升条数） |
| **行为** | 开连接循环 claimDue；**不** `dispatchNext`；日志可观测 |
| **副作用** | 只改 Task 状态/last_fired；无 Run |
| **本号** | **真** |

### 5.3 `acceptResult` 成功路径（改契约 · 多次）

| 项 | 内容 |
|----|------|
| **前置** | 既有 lease/CAS 成功写 Run SUCCEEDED |
| **行为** | 读 Task `schedule_spec`：若 `null` 或 `!recurring()` 或 `advance(...).isEmpty()` → 现逻辑 `Task SUCCEEDED` + `notifyDelivery`；若 `advance` 得 `next` → 写 `next_fire_at=next`、`last_fired_at`（已有则保留晋升值）、**status=`SCHEDULED`**（非 SUCCEEDED）+ `notifyDelivery`（终态语义：本次开火完成；交付载荷用 SUCCEEDED 语义或钉「FIRING_SUCCEEDED」——待决 **S3** 推荐仍用 `BackgroundTaskStatus.SUCCEEDED` **仅表示本次开火结果进交付**，Task 行状态回 SCHEDULED；交付 `terminalStatus` 字段用 SUCCEEDED 表示「这次跑成功」） |
| **失败** | 可重试失败不推进 next_fire；耗尽 FAILED + notify；**不**自动跳下一火（S3=A） |
| **本号** | **真**（改 DefaultTaskRuntime + 必要 Repo `reschedule`） |

### 5.4 `BackgroundTaskRepository.rescheduleAfterSuccessfulFire`

| 项 | 内容 |
|----|------|
| **声明** | `boolean rescheduleAfterSuccessfulFire(Connection, BackgroundTaskId, Instant nextFireAt, Instant now)` |
| **行为** | 期望当前可从 RUNNING（或写 result 同事务）→ `SCHEDULED`；更新 `next_fire_at`；CAS 防丢 |
| **本号** | **真** |

### 5.5 `SchedulePromoteTicker.tick`

| 项 | 内容 |
|----|------|
| **行为** | 调 `promoteDueScheduled(batch)`；吞单拍异常打 WARN |
| **本号** | **真** |

### 5.6 `requestCancel`（钉清 · 可选加固）

| 项 | 内容 |
|----|------|
| **SCHEDULED 无 Run** | `CANCELLED`；与晋升竞态：CAS `SCHEDULED→CANCELLED` 优于无条件 `writeResult`（**S6=A**） |
| **已 CREATED/READY/RUNNING** | 沿用 2.5.4 |
| **本号** | 加固 CAS；不扩侧栏 |

## 9. 验收断言

```text
[ ] SCHEDULED + next_fire_at 已到期 → 被晋升为 CREATED；dispatch 可认领执行
[ ] 未到期 SCHEDULED → 不被 claimNextExecutable / 不被晋升
[ ] 单次 relative/at：执行成功 → Task SUCCEEDED + 走 2.5.6/2.5.7 交付；advance 空
[ ] 多次 every/cron：执行成功 → Task 回 SCHEDULED 且 next_fire_at 推进；交付钩仍触发（本次成功可见）
[ ] 多次失败耗尽 → FAILED；不推进下一火（按 S3）
[ ] 取消未开火 SCHEDULED → CANCELLED；与晋升竞态不双活
[ ] 无新 Cron 表；V024 原文零改；claim SQL 仍排除 SCHEDULED
[ ] 禁区零 diff；窄编译通过
```
