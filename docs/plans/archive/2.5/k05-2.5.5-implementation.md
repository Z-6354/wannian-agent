### 1.1 G4 确认路径（钉死）

```text
BackgroundAccepted
  → insert TaskReviewPending(PENDING)
  → sealReply「待你确认…」(taskDraft=null)  // 同拍 Turn 完成
  → SSE/消息携带 reviewId（outbox 或消息 metadata；实施选最短）

用户 POST confirm(reviewId)
  → CAS PENDING→CONFIRMED（未过期）
  → TaskRuntime.prepare(proposal)
  → 独立 commit 路径：新助手短消息 = acknowledgementText + CommitTurnPlan(taskDraft)
     （不重跑 Loop；不占用新用户 Turn；可用「系统附言」或同会话助手消息）
  → 立即 Task 由既有 2.5.4 Ticker 拉取

用户 POST reject
  → CAS PENDING→REJECTED
  → 可选助手短文「已取消创建任务」（无 Draft）
```

> 若「独立 commit 无 Turn」撞现有 TurnCommitter 约束：允许开一个**轻量** `TaskReviewService.confirm` 内直接 `insertFromDraft` **仅当**无法走 CommitTurnPlan——但 P2 不变量要求 Draft 经 CommitTurnPlan。  
> **优先：** confirm 时创建短 Turn 或复用「附言 commit」API；实施时先查是否已有无 Loop 的 commit 入口；没有则最小加 `TurnEngine.commitTaskAfterReview(...)`（或等价）走 freeze+commit 带 Draft。**禁止**绕过 Committer 直接 insert（除非实施中证明 Committer 无法附言且回报修订）。

### 1.2 G5 工具契约（钉死）

| 项 | 内容 |
|----|------|
| name | `propose_background_task` |
| 可见 | 主 Loop ToolRuntime 注册（本号新增 Adapter/描述符） |
| args | `taskType`, `inputJson`, `scheduleSpec?`（JSON）, `acknowledgementText`, `notifyPolicy?` |
| 行为 | **不**写 Task；返回 observation「已形成提案，等待策略与用户确认」；Loop 在工具成功后组装 `TaskProposal(source=USER_LOOP, …)` 调 Policy |
| Policy Reject | Loop → ControlledFailure 或 Final「无法后台化：reason」；不 BackgroundAccepted |
| Policy Accept | Loop → BackgroundAccepted(proposal, ack, trace) |

### 1.3 ErrorCodes（本号）

| 码 | 用途 |
|----|------|
| 复用 `ILLEGAL_STATUS` | confirm/reject 非 PENDING |
| 复用 `ILLEGAL_ARGUMENT` | 坏 reviewId / 过期参数 |
| 新增 `TASK_REVIEW_EXPIRED` | Pending 过期 |
| 新增 `TASK_REVIEW_NOT_FOUND` | 无此 Pending |
| `BACKGROUND_NOT_ENABLED` | **成功路径删除**；码可保留注册供历史，TurnEngine 不再因 BackgroundAccepted 返回它 |
